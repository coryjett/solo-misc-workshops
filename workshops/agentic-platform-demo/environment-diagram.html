Agent platform demo environment

Registry, gateway and runtime on one Kubernetes cluster. The registry decides what exists and who owns it. The gateway is the only path to it, and it enforces identity and scope on every call.

Control plane. The registry holds every agent, MCP server and model with its owner, data class and approvals. Access policies scope what each team can see and change.

Data plane. agentgateway carries every tool and model call. Identity, scope, guardrails and token exchange are enforced per call, not per app.

Runtimes. kagent runs agents on Kubernetes. The registry can also target cloud agent runtimes. Approved servers can be published straight to the gateway with no compute.

Identity. Keycloak keeps the demo self-contained. Pointing sign-in at Entra ID is configuration; the on-behalf-of exchange against Entra is validated on your tenant.

Down-scoped SaaS tools. One front door serves a WorkIQ and a GitHub stand-in. Each group gets its own slice of the same servers, enforced on tools/list and tools/call. In production only the target host changes.

Token flow. The user token is validated and never forwarded. Each backend gets a token the gateway STS issued for the same user.

A2A. Users can discover and call only agent-a. agent-a reaches agent-b and agent-c with its own identity. agent-b calling agent-c is refused at the gateway, not inside the agent.

Limits today. A2A authorization is per agent route, not per method or skill. Content guardrails for A2A use ext_proc. A2A rate limits count requests, not tokens.

  1. 1The catalog shows what exists, who owns it and what data it touches, plus agents running that nobody registered.
  2. 2A developer submits a new agent version. Their write is staged for approval, not published.
  3. 3The admin approves it, then publishes an MCP server to the Virtual runtime. The registry creates the gateway route and backend, carrying the per-tool scope rule.
  4. 4A client calls as a user. The gateway checks the JWT, filters tools by scope, masks PII and mints an on-behalf-of token for the backend.
  5. 5An approved MCP server or agent is deployed to kagent. Agents reach their tools through the same gateway, so they inherit the same rules.
  6. 6Audit from both planes: registry events show who submitted, approved and deployed; gateway traces show every call.

Catalog contents, teams and data in this demo are fictional.
